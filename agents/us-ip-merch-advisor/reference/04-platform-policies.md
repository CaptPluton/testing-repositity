# 04 — Правила площадок и POD-сервисов (часто строже закона)

Общее: все крупные площадки действуют по модели «уведомление → удаление → страйк → бан» и не оценивают fair use. Повторные жалобы ведут к закрытию аккаунта и часто к блокировке связанных аккаунтов (по данным KYC, банковским реквизитам, IP). Проверять актуальные тексты политик при каждом ответе.

|---|---|---|---|

## DMCA-процедура на площадке (17 U.S.C. §512)

1. Правообладатель подаёт notice (§512(c)(3)) → площадка удаляет и уведомляет продавца.
2. Продавец при наличии правовой позиции подаёт counter-notice (§512(g)(3)): идентификация материала, заявление под присягой о добросовестной уверенности в ошибке, согласие на юрисдикцию федерального суда (для нерезидентов — по месту площадки), подпись.
3. Площадка пересылает правообладателю; если за 10–14 рабочих дней нет иска — восстанавливает (часть площадок восстанавливают неохотно, особенно при repeat infringer-статусе).
4. Ложные notice/counter-notice — ответственность по §512(f).

Для жалоб по ТЗ формального counter-notice в законе нет — только внутренняя апелляция площадки; обычно требуют письмо правообладателя об отзыве жалобы.

## Практические правила для аккаунта

- Один страйк — повод пересмотреть всю линейку, а не только один листинг: свипы находят остальное.
- Не открывать второй аккаунт после бана — нарушение ToS, часто обнаруживается и ведёт к постоянному запрету и удержанию средств.
- Хранить доказательства оригинальности каждого дизайна (исходники, даты) — помогают в апелляциях.
- Для лицензированных товаров — держать копию лицензии/письма правообладателя; площадки запрашивают.
