# Сценарий: пятничный обзор стратегии (weekly-review)

Пятница, вечер. Цель: посчитать метрики по дозревшим когортам, принять решения по A/B и стратегии через «ворота выборки» (плейбук), обновить отчёт и отчитаться Яне. Изменения стратегии — только с подтверждением Яны.

## Шаги

1. **Подготовка**: `git pull`, lock, config + state. Реплей `pending-asana.json`.
2. **Метрики**: `python3 sales-agent/report/build_report.py --json` → недельные когорты (по дате отправки): sent, bounced, replies за 3/7/14 дней, созвоны, разрезы по нишам/вариантам/email_type. Скрипт упал → почини данные (битые даты видны в его ошибке) или откати последнее изменение state; метрики «в голове» не считать.
3. **Сверка**: (а) `days[дата].cold_drafts` vs число лидов с подготовкой письма этой датой в history; (б) `days[дата].confirmed_sent` vs число лидов с `sent_at` этой даты. Расхождения — исправь счётчики и зафиксируй в выводах недели.
4. **Эксперименты** (`weekly.json → experiments`) — пороги считаются ТОЛЬКО по когортам с `mature=true` из `--json`:
   - для `running`: достигнуты пороги решения (≥40 отправок на вариант И суммарно ответов по эксперименту ≥5 И (разница ответов ≥3 в абсолюте ИЛИ один ≥2× другого))? → `decided`, победитель становится дефолтом (правка шаблона отдельным коммитом с id эксперимента). 3 недели без разницы → `no_difference`, следующий фактор;
   - нет активного эксперимента → предложи следующий из очереди факторов (CTA → архетип темы → длина 70/120 слов → кейс vs расчёт), оформи гипотезу, статус `proposed`;
   - максимум один новый эксперимент в неделю. Фоллоу-ап №1 и holding-ответы можно тестировать параллельно (бесплатный контур, не входит в лимит).
5. **Решения по воротам** (плейбук, «Ворота выборки»): проверь каждое ворото по цифрам. Срабатывает → задача «Согласовать: {суть изменения}» в Asana («Настройка системы», assignee Яна, в описании цифры и конкретная правка). Применять изменение можно ТОЛЬКО после закрытия/подтверждения задачи Яной — «молчание = согласие» не работает. Подтверждённые на прошлой неделе → примени (config/шаблоны, отдельный коммит с id решения).
6. **weekly.json**: запиши неделю — `metrics` (из --json), `experiments` (статусы), `decisions` ({id, date, what_changed, file, expected_effect, review_after}), `conclusions` (3–5 предложений человеческим языком: что работает, что нет, что делаем).
7. **Отчёт**: пересобери xlsx и создай НОВЫЙ файл на Диске (`create_file`: base64 xlsx, contentMimeType `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` — конвертируется в Google Таблицу), имя «OMG — Отчёт по рассылке (YYYY-MM-DD)». Инструмента перезаписи файла на Диске нет — не пытайся. Новый file_id/URL → `activity-log → report`; свежая ссылка идёт в status update (шаг 8) и push (шаг 10).
8. **Status update в Asana**: `create_project_status_update` в проект «Продажи» — цифры недели (отправлено, ответы, reply rate, созвоны), статус эксперимента, вывод, ссылка на свежий отчёт; цвет: green (движется), yellow (метрики ниже «Ориентиров метрик» плейбука), red (система простаивала/сломан коннектор).
9. **Гигиена**: `no_response`-кандидаты на реактивацию на следующую неделю; лиды, зависшие в `drafted` >5 дней; напоминания по незакрытым созвонам. Сними lock, финальный коммит + push, `last_run_at.weekly`.
10. Push Яне: краткий итог недели одной строкой + ссылка на таблицу.
