# Сценарий: поиск клиентов, холодные письма, фоллоу-апы (v2.1)

Будни, утро. Перед началом прочитай `playbook.md` и `config.yaml` — правила git/lock, Asana, fallback и статусы там. Режим дня: холодные письма и реактивация — только в `cold_days` (вт–ср–чт); понедельник и пятница — только фоллоу-апы и DM.

## 0. Подготовка

1. `git fetch && git checkout claude/sales-agent-email-odes7k && git pull`. Поставь lock по правилам плейбука.
2. Прочитай `config.yaml`, `state/leads.json`, `state/activity-log.json`. Реплей `pending-asana.json`, если Asana жива. Флаг `connectors.gmail_write=down` снимается **лениво**: при первом успешном `create_draft`/`create_label` этого запуска поставь `gmail_write=ok` и `flags.gmail_down_notified=null` тем же коммитом; ошибка авторизации → флаг остаётся, письма в outbox. `gmail_read` проверяется пробным `search_threads`.
3. **Опрос подтверждений отправки** (источники по приоритету; чат свежая cron-сессия НЕ видит — подтверждение из чата действует только в интерактивной сессии и немедленно дублируется агентом в описание Asana-задачи):
   - задачи секции «Отправить сегодня» (по gid из `activity-log → asana` + поиск по секции): **завершена** → всем лидам батча `sent`, `sent_at` = дата завершения; в тексте ОПИСАНИЯ задачи есть отметка Яны («отправила всё/частично: …», дата) → по ней. При каждом проставлении `sent_at` инкрементируй `activity-log.days[<sent_at>].confirmed_sent`;
   - задача по сохранённому gid не находится (404/удалена) → это НЕ подтверждение и НЕ отказ: пересоздай задачу по существующему outbox-файлу (due сегодня), новый gid в activity-log, push «задача батча пересоздана — подтвердите отправку»; лиды остаются `drafted`;
   - **фиксация не только холодных**: фоллоу-апам подтверждённого батча проставь `sent` в соответствующей записи `followup_history` и `pending_draft=false`; DM — запись в history {date, action: "dm отправлен", channel};
   - **обработав подтверждение — заверши задачу сам** (`update_tasks completed=true`) и допиши в описание «зафиксировано агентом: sent_at=<дата>, N лидов → sent»; gid — в `activity-log → asana.processed_confirmations`. Guard «висит >2 дней» применяется только к незавершённым задачам без отметки;
   - Gmail жив → дополнительно сверь `in:sent to:<email>` по всем `drafted` И по всем `sent`-лидам с `external.thread_id=null`: найденным допиши `sent_at` (если пуст, датой письма из in:sent) и `external.thread_id`.
4. Guard'ы (при срабатывании — только фоллоу-апы по подтверждённым, без новых холодных):
   - конфиг не заполнен → push + стоп;
   - неподтверждённых `drafted` ≥ `max_pending_drafts` ИЛИ незавершённая задача «Отправить сегодня» без отметки старше 2 рабочих дней → пауза холодных, обнови due задачи, push «письма копятся неотправленными»;
   - `last_run_at.inbox` старше 1 дня в будни (null считается «старше») → алерт задачей в «Настройка системы», флаг `flags.inbox_stale_notified` (сбрасывает inbox при успешном запуске); НО если причина — `gmail_read=down` и `gmail_down_notified` уже стоит, новый алерт не создавать.
5. Gmail жив → `list_labels`, недостающие метки из `gmail_labels` создать.

## 1. Фоллоу-апы и реактивация (каждый запуск)

1. Кандидаты на фоллоу-ап: лиды `sent` с ПОДТВЕРЖДЁННОЙ отправкой последнего касания (`sent_at` холодного или поле `sent` последней записи `followup_history`), без ответа, у которых прошло ≥ следующего интервала `followup_after_days` (D+3/D+7/D+14) и `followups_sent < followups_max`. `replied`-лидов prospecting не трогает: если лид ответил и замолчал после нашего ответа — этим занимается inbox.
2. Для каждого: письмо по `templates/followup.md` — reply в цепочку `external.thread_id` при живом Gmail. thread_id нет и поиск `in:sent to:<email>` пуст → фоллоу-ап новым письмом с темой «Re: <исходная тема>», факт зафиксируй в history. Gmail мёртв → в outbox-файл дня. Обнови `followup_history` (запись {n, prepared, sent: null, channel: "email"}), `pending_draft=true`. Висит неотправленный фоллоу-ап >2 дней → новый не готовить.
3. **no_response**: ставится, когда 3-й фоллоу-ап подтверждённо отправлен (`followup_history[3].sent` заполнен) и с этой даты прошло ≥14 дней без ответа. `reactivation_after_days` отсчитывается от даты отправки последнего касания.
4. **DM-касания**: лиды с подтверждённой отправкой D+`dm_touch_after_days` без ответа, у которых есть `lpr_vk`/`lpr_tg`, — сообщение по `templates/dm.md` в `outbox/YYYY-MM-DD-dm.md`; отправляет Яна, канал и дата — в history.
5. **Реактивация** (только в `cold_days`): `no_response`-лиды старше `reactivation_after_days` — одно письмо с новым углом; входит в квоту дня, максимум 2 в день, вариант A/B — на общих основаниях.

## 2. Квота дня (только в cold_days)

Доступно = `daily_cold_email_limit` − (холодные за сегодня по Asia/Omsk из activity-log, включая реактивации). Распределение по нишам — `niche_quota`. Если 0 — к шагу 5.

## 3. Поиск новых лидов

0. **Сначала резерв**: кандидаты из leads.json со статусом `backlog` — перепроверь дедуп/блоклист, дособери персонализацию. Повторно отклонённый backlog-лид — причина в notes, чтобы не перебирать его каждый день. Только недостающее до квоты добирай поиском.
1. WebSearch по нишам/географии ICP. **WebFetch внешних сайтов недоступен — не ретраить**; факты из сниппетов, максимум 2 запроса на кандидата сверх основного. Email не найден → `backlog`.
2. **Поиск ЛПР — обязательный этап**: имя владельца/директора (сниппеты «О нас», отзывы, rusprofile/checko, VK, TG). Заполняй `contact_name`, `lpr_vk`, `lpr_tg`, `email_type`, `has_contact_name`. Без имени ЛПР — второй приоритет.
3. **Соцсети — обязательный этап проработки** (по сниппетам WebSearch: `site:vk.com`, `site:instagram.com`, `site:t.me`, 2ГИС/Яндекс.Карты): смотрим **ВК, Instagram и Telegram** — это основные соцсети аудитории в РФ. Оцени подписчиков, частоту постов, дату последней активности, ведут ли рекламу, что пишут в отзывах (рейтинг, жалобы, хвалят ли конкретных мастеров/врачей). **Facebook игнорировать полностью**: в РФ им почти не пользуются — его наличие/отсутствие не сигнал, данные с него не собирать и в письмах не упоминать. Рабочий аргумент про Instagram: «аудитория есть, но рекламу в нём в РФ не купить — переносим трафик в ВК». Всё в `notes`; ссылки — в `lpr_vk`/`lpr_tg`.
4. Отсев: дедуп по домену сайта против всего leads.json (freemail — по полному адресу); `blocklist_domains`; disqualifiers; noreply. Gmail жив → `to:@домен OR from:@домен`: переписка была → пропустить.
5. Кандидатов на ~20% больше квоты, отбери лучших (персонализация + соцразведка + имя ЛПР). Лучше 8 сильных, чем 10 слабых.

## 4. Холодные письма

Для каждого лида в пределах квоты:
1. **Вариант A/B** активного эксперимента (`weekly.json → experiments`, status=running): счёт лида дня = `activity-log.days[сегодня].cold_drafts + 1` на момент подготовки (переживает падение запуска); нечётный → A, чётный → B. Порядок обработки: ниши по приоритету `icp.industries`, внутри ниши — по алфавиту id. Запиши `variant`, `experiment_id`. **Варианты отличаются ТОЛЬКО фактором эксперимента** (для EXP-001 — только CTA; тема у обоих — дефолтный архетип «наблюдение»).
2. Письмо по `templates/cold-email.md`: нишевый блок, персонализация, тема по правилам, гейткипер-блок для generic-ящиков (кроме писем с личным обращением к ЛПР), UTM-ссылка, opt-out.
3. Gmail жив → `create_draft`; нет → блок в outbox-файл дня.
4. Лид в leads.json (статус `drafted`, `pending_draft=true`, все поля схемы) — **state после каждого письма**, коммит каждые 2–3 лида, инкремент `cold_drafts` сразу.

## 5. Завершение

1. Outbox-файл (если писем нет — пропусти): сгруппируй по часовым поясам получателей, укажи окно 10:00–12:00 локального времени лида и пересчёт на время Яны (Бангкок, UTC+7): Новосибирск 0 ч; Омск −1; Екатеринбург −2; Самара −3; Москва/СПб/Казань −4. Инструкция: по одному письму с интервалом 3–5 минут. Чек-блок — как памятка; каналы подтверждения — Asana-задача или чат.
2. Asana: задача в «Отправить сегодня» — «Отправить: N холодных + M фоллоу-апов (+K DM)», due сегодня, ссылка на файл/черновики, id лидов, строка «ОТМЕТКА ОБ ОТПРАВКЕ: …». Gid — в activity-log. (Asana мертва → `pending-asana.json`.)
3. Обнови activity-log (счётчики дня Asia/Omsk, `last_run_at.prospecting`). Сними lock. Финальный коммит + push.
4. Некритично: `python3 sales-agent/report/build_report.py`, закоммить xlsx.
5. Push Яне (только если есть что отправлять): сколько и где. Финальный отчёт: найдено/подготовлено/фоллоу-апы/DM/пропуски.
