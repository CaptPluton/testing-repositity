# Сценарий: поиск клиентов, холодные письма, фоллоу-апы (v2)

Будни, утро. Перед началом прочитай `playbook.md` и `config.yaml` — правила git/lock, Asana, fallback и статусы там. День недели определяет режим: холодные письма — только в `cold_days` (вт–ср–чт); понедельник — фоллоу-апы и реактивация; пятница — фоллоу-апы, без холодных.

## 0. Подготовка

1. `git fetch && git checkout claude/sales-agent-email-odes7k && git pull`. Поставь lock (`state/.run-lock`), закоммить, запушь (правила в плейбуке).
2. Прочитай `config.yaml`, `state/leads.json`, `state/activity-log.json`. Проверь `connectors.*`: есть очередь `pending-asana.json` и Asana жива — реплей. Gmail/write снова жив после простоя — сними флаг.
3. **Опрос подтверждений отправки**: возьми задачи секции «Отправить сегодня» (Asana) и последние сообщения Яны в чате. Задача завершена / Яна подтвердила («отправила») → всем лидам батча статус `sent`, `sent_at` = дата подтверждения (уточни дату из комментария, если была не сегодня). Частично («отправила все кроме X») → по списку. Gmail жив → дополнительно сверь `in:sent to:<email>` по всем `drafted` — найденным ставь `sent`+`sent_at`+`external.thread_id`.
4. Guard'ы (при срабатывании — только фоллоу-апы по подтверждённым, без новых холодных):
   - конфиг не заполнен → push + стоп;
   - неподтверждённых `drafted` ≥ `max_pending_drafts` ИЛИ задача «Отправить сегодня» висит >2 рабочих дней → пауза холодных, обнови due задачи, push «письма копятся неотправленными»;
   - `last_run_at.inbox` старше 1 дня (в будни) → алерт Яне (Asana «Настройка системы», один раз по флагу).
5. Убедись, что Gmail-метки из конфига существуют (когда gmail жив); недостающие создай.

## 1. Фоллоу-апы и реактивация (каждый запуск)

1. Кандидаты: лиды `sent`/`replied`-без-ответа-Яны с ПОДТВЕРЖДЁННОЙ отправкой последнего касания, у которых прошло ≥ следующего интервала из `followup_after_days` (D+3/D+7/D+14 от `sent_at` последнего касания в `followup_history`) и `followups_sent < followups_max`. Лид с ответом (`replied`+) — не фоллоу-апить, им занимается inbox.
2. Для каждого: письмо по `templates/followup.md` (reply в ту же цепочку при живом Gmail; иначе в outbox-файл). Обнови `followups_sent`, `followup_history` (пометь «подготовлен, не подтверждён»). Висит неотправленный фоллоу-ап-черновик >2 дней → новый НЕ готовить.
3. Исчерпаны все касания без ответа → статус `no_response` (не `not_interested`!).
4. **DM-касания**: лиды с подтверждённой отправкой D+`dm_touch_after_days` без ответа, у которых есть `lpr_vk`/`lpr_tg`, — короткое сообщение по `templates/dm.md` в `outbox/YYYY-MM-DD-dm.md`. Отправляет Яна с личного аккаунта; канал и дата — в `history`.
5. **Реактивация**: `no_response`-лиды старше `reactivation_after_days` — одно новое письмо с новым углом (сезонность/новый кейс), считается холодным письмом дня (входит в лимит!), максимум 2 таких в день.

## 2. Квота дня (только в cold_days)

Доступно = `daily_cold_email_limit` − (холодные за сегодня по Asia/Omsk из activity-log) − реактивации шага 1.5. Распределение по нишам — `niche_quota`. Если 0 — переходи к шагу 5.

## 3. Поиск новых лидов

1. WebSearch по нишам/географии из ICP. **WebFetch внешних сайтов недоступен (прокси) — не ретраить**; факты подтверждай поисковыми сниппетами, максимум 2 запроса на кандидата сверх основного. Email не нашёлся в сниппетах — кандидат в `backlog`, не мучить.
2. **Поиск ЛПР — обязательный этап**: имя владельца/директора (страница «О нас» в сниппетах, отзывы с ответами владельца, rusprofile/checko в выдаче, VK-сообщество, Telegram). Заполняй `contact_name`, `lpr_vk`, `lpr_tg`, `email_type` (personal/generic), `has_contact_name`. Лид без имени ЛПР — второй приоритет при отборе.
3. Отсев: дедуп по домену сайта против ВСЕГО leads.json (для freemail-адресов — по полному адресу); `blocklist_domains`; disqualifiers ICP; noreply-адреса. Gmail жив → поиск `to:@домен OR from:@домен` по ящику: переписка уже была → пропустить.
4. Набери кандидатов на ~20% больше квоты, отбери лучших (сильная персонализация + имя ЛПР).

## 4. Холодные письма

Для каждого лида в пределах квоты:
1. Вариант A/B активного эксперимента (см. `weekly.json → experiments`, статус `running`): нечётный по счёту лид дня → A, чётный → B. Запиши `variant`, `experiment_id`.
2. Письмо по `templates/cold-email.md`: нишевый блок, персонализация, тема по правилам, гейткипер-блок для generic-ящиков, UTM в ссылку сайта, opt-out.
3. Gmail жив → `create_draft`; нет → блок в outbox-файл дня.
4. Лид в `leads.json` (статус `drafted`, все поля схемы, history) — **записывай state после каждого письма**, коммить каждые 2–3 лида.

## 5. Завершение

1. Если письма ушли в outbox: заверши файл чек-блоком:
   ```
   ## Подтверждение отправки (заполняет Яна)
   - [ ] отправлено всё … / частично: <кто>
   ```
   и сгруппируй письма по часовым поясам получателей с рекомендованными окнами отправки (10:00–12:00 локального времени лида, в скобках — время Яны, Бангкок UTC+7). Инструкция: слать по одному с интервалом 3–5 минут.
2. Asana: создай/обнови задачу в «Отправить сегодня» — «Отправить: N холодных + M фоллоу-апов (+K DM)», due сегодня, ссылка на файл/черновики, id лидов. (Asana мертва → `pending-asana.json`.)
3. Обнови `activity-log`: счётчики дня (Asia/Omsk), `last_run_at.prospecting`. Сними lock. Финальный коммит + push.
4. Некритичный шаг (падение не блокирует): `python3 sales-agent/report/build_report.py`, закоммить xlsx.
5. Push Яне: сколько готово к отправке и где. Финальный отчёт: найдено/подготовлено/фоллоу-апы/DM/пропуски и почему.
